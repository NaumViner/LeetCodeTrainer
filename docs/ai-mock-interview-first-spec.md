# אפיון מוצר חדש — AI Mock Interview

תאריך: 06.09.2026 · גרסה: 1.0 · סטטוס: אפיון לביצוע, לפני שינוי האפליקציה.

זהו מסמך העבודה לשינוי ב־`v3`. הוא מחליף החלטות מוצר סותרות במסמכי האקדמיה וה־Interview First הקודמים. מסע האורח מומש מקומית; מצב המימוש והבדיקות מפורט ב־[דוח המימוש](interview-first-implementation.md). קריטריוני ההשקה הציבורית עדיין דורשים בדיקה בסביבת הענן.

## 1. המוצר שאנחנו בונים

**נכנסים לקישור, בוחרים כמה הגדרות קצרות ומתחילים ראיון AI אמיתי ללא הרשמה.**

הראיון הוא המוצר המרכזי: מראיין קולי, פתרון בעיית קוד, הבנת החשיבה בזמן אמת, Follow-up כשמתאים ומשוב לאחר הראיון. מסלולי לימוד, אבחון, תרגול ותוכניות הכנה לא יעמדו בדרך אליו.

הראיון הראשון פתוח לאורח. לאחר סיום או נטישה מוצעת הרשמה לשמירת הראיון והפרטים ולהמשך שימוש. ראיון נוסף דורש חשבון. הערכת יכולות מוצעת רק אחרי הרשמה, ורק כפעולה שהמשתמש בוחר במפורש.

המסירה הנוכחית כוללת אפיון זה, [מדריך לפריסה ציבורית](public-launch-runbook.md) ו[תבנית הגדרות Production](../deploy/production.env.example). שינוי המסכים, הרשאות האורח והפריסה בפועל הם שלב הביצוע הבא.

## 2. מסלול המשתמש

1. פתיחת הדומיין מציגה מסך קצר עם הגדרות הראיון וכפתור מרכזי: **התחלת ראיון**.
2. ההגדרות כבר מלאות בברירות מחדל. אין שאלון אישי, אימייל, הרשמה או אבחון.
3. לחיצה על התחלה יוצרת זהות אורח מאחורי הקלעים, בוחרת שאלה ופותחת את מסך הראיון.
4. במסך הראיון מבקשים הרשאת מיקרופון ומחברים את המראיין הקיים. המתנה להרשאה אינה מעכבת את פתיחת המסך ואינה צורכת את הניסיון.
5. השעון מתחיל רק לאחר הפעלת החיבור הקולי בפועל, כמו היום.
6. המשתמש מקיים ראיון מלא. רענון או חיבור מחדש ממשיכים את אותו הראיון.
7. בסיום מופיע סיכום הראיון והצעה לשמור אותו באמצעות הרשמה.
8. בנטישה יזומה מופיעה הצעה לשמור את מה שבוצע. סגירת הדפדפן מטופלת בעת החזרה לאפליקציה.
9. הרשמה שומרת את הראיון, הקוד, ההערכה והעדפות המשתמש. לאחר מכן אפשר להתחיל ראיון נוסף בלי אבחון חובה.

אפשר להתחבר לחשבון קיים מקישור קטן במסך הפתיחה. למשתמש רשום מוצגות ההעדפות האחרונות שלו; ראיון פעיל מקבל כפתור המשך במקום יצירת ראיון מקביל.

## 3. מסך ההתחלה — ארבע בחירות בלבד

| בחירה      | אפשרויות בגרסה הראשונה                                  | ברירת מחדל מוצעת |
| ---------- | ------------------------------------------------------- | ---------------- |
| שפת הראיון | ENGLISH / HEBREW                                        | ENGLISH          |
| שפת קוד    | Python / Java                                           | Python           |
| טווח קושי  | Easy, Medium, Hard, Easy–Medium, Medium–Hard, Easy–Hard | Easy–Medium      |
| משך הראיון | 30 / 45 / 60 דקות                                       | 30 דקות          |

ברירות המחדל הן החלטת אפיון חדשה ואפשר לשנותן לפני המימוש. Python ו־Java ומשך 30/45/60 דקות כבר נתמכים בקוד. לא מציגים שפה נוספת לפני שהעורך, השמירה והמראיין תומכים בה בפועל.

טווח קושי נבחר בשדה יחיד. למשל Easy–Hard כולל את שלוש הרמות; Easy–Medium כולל את שתיהן. אין צורך לסמן מספר תיבות או לבחור קושי לכל שאלה. הבחירה אינה חסומה לפי אבחון או ציון קודם.

**סגנון מראיין נשאר זמין:** מתג משני קטן **נוח / קשוח**, עם **נוח** כברירת מחדל. זו אפשרות נוספת שאפשר לשנות בלי מסך נוסף ובלי לחייב החלטה נוספת. המיפוי הפנימי נשאר `beginner` / `faang_tough`. סגנון המראיין אינו משנה את טווח הקושי שנבחר.

אין בחירת נושא, שאלה, חברה, תפקיד, רמת ניסיון, מסלול לימוד, Coverage/Improvement/Learning/Custom או שפת ראיון Auto. אין צורך בפרופיל מלא כדי להתחיל. השפה שנבחרה נשמרת לראיון ולמשוב; העורך נשאר משמאל לימין גם בראיון בעברית.

מתחת לכפתור: **ראיון ראשון ללא הרשמה · נדרש מיקרופון**. ליד בקשת המיקרופון יופיע הסבר קצר שהקול מועבר לספק AI לצורך הראיון ושקוד ותמלול נשמרים לצורך המשוב.

## 4. בחירת השאלה — לפי הנושא שהכי פחות נבחן

משתמשים במנגנון `selectCoverageInterview` הקיים. הוא הופך למסלול הבחירה הקבוע, גם אחרי שהמשתמש עבר על כל הנושאים. לא עוברים אוטומטית ל־Learning.

המשמעות של נושא שנבחן נשארת כמו היום: ספירת **ראיונות שהושלמו**. ראיון פעיל או נטוש אינו מגדיל כיסוי ואינו ממציא עדות ליכולת. ניצול הראיון הראשון וצבירת כיסוי הם שני דברים נפרדים.

סדר הבחירה:

1. משתמשים רק בשאלות פעילות מהאוסף הקיים, עם נוסח מאושר וזמינות לראיון.
2. מסננים לפי טווח הקושי שהמשתמש בחר.
3. כל עוד נותרו נושאים ללא ראיון שהושלם, בוחרים מתוכם נושא שיש עבורו שאלה מתאימה.
4. אחרי כיסוי מלא, בוחרים בין הנושאים בעלי מספר הראיונות המינימלי שיש עבורם מלאי מתאים.
5. בשוויון בוחרים באקראי; נמנעים משני הנושאים השונים האחרונים ככל האפשר.
6. בתוך הנושא מעדיפים שאלה שהמשתמש לא השלים בעבר. משתמשים בחזרה רק כשאין חלופה במאגר המתאים.

אצל אורח חדש כל המונים הם אפס. אין צורך באבחון כדי לבחור לו שאלה. אחרי ההרשמה הראיון הראשון נכלל בהיסטוריה ובכיסוי פעם אחת בלבד, אם הושלם.

אם הטווח הנבחר אינו מאפשר שאלה באף אחד מהנושאים שעדיין לא כוסו, נשמרת התנהגות הכשל של המנגנון הקיים: הודעה קצרה והצעה להרחיב את הטווח. לא משנים קושי בשקט ולא צורכים את הניסיון. אין צורך להציג את שמות הנושאים למשתמש בזמן הראיון.

**מלכודת מימוש:** כיבוי `INTERVIEW_SELECTION_MODES_ENABLED` מפעיל כיום Learning בלבד. לכן הסרת בחירות מהמסך דורשת קיבוע Coverage בשרת; היא אינה נעשית באמצעות כיבוי הדגל הזה. גם בקשה ששונתה ידנית לא תוכל לבחור מסלול אחר בזרימה החדשה.

## 5. ה־Brain והניתוח בזמן אמת נשמרים

משמרים את ההנחיות, אישיות המראיין, ספקי ה־AI, כלי השליטה, מנגנון הראיות והמשך השיחה הקיימים. לא בונים מנוע מקביל לאורח ולא נותנים לו ראיון מצומצם.

| רכיב        | דרישת שימור                                                                                |
| ----------- | ------------------------------------------------------------------------------------------ |
| מראיין נוח  | שאלה קצרה בכל פעם, הכוונה מדודה, בלי מסירת פתרון                                           |
| מראיין קשוח | תגובות ניטרליות ומינימליות, בלי רמזים, שבחים או הכרזת נכונות                               |
| הבנת הפתרון | שער המוכנות הקיים: אלגוריתם, מבני נתונים/מצב, סדר פעולות, טיעון נכונות, מקרי קצה וסיבוכיות |
| שלבי שיחה   | מבוססים על אירועים שנשמרו; אפשר לדלג ולחזור כפי שהבקר הקיים מאפשר                          |
| שליטת השרת  | מעברים וכלים מאומתים, בעלות על הראיון, מניעת אירוע כפול וסדר ראיות תקין                    |
| קול         | תורות דיבור, הפרעות, חיבור מחדש ומצב חיבור ברור                                            |
| עורך        | שמירה אוטומטית, גרסאות ומניעת דריסת קוד בעימות שמירה                                       |
| המשכיות     | שחזור מצב, שאלה פעילה, Follow-up, מוכנות, קוד, זמן והקשר השיחה הקיים                       |

בחיבור מחדש המראיין ממשיך מהמקום שבו נעצר; הוא לא פותח מחדש את הראיון ולא מחליף שאלה. תצוגת השיחה הקיימת של שש האמירות האחרונות ומגבלות חשיפת מידע נשמרות. נתוני אורח אינם נכנסים למטמון משותף בין משתמשים.

דיוק בהבטחת המוצר: המראיין מנתח את השיחה בזמן אמת ומקבל הקשר קוד בעת הגשה כפי שממומש כיום. ציון ה־AI המפורט נוצר **לאחר השלמת הראיון**. הקוד כיום אינו מורץ בסביבת בדיקות פעילה. לא מציגים הרצת קוד, ניתוח כל הקלדה או ציון חי כיכולות קיימות.

לפני שינוי הזרימה מתעדים בסיס השוואה של חיבור, תורות דיבור, הפרעות, עברית/אנגלית ושחזור. ירידה מהותית באיכות מול הבסיס חוסמת שחרור; שינוי ממשק לא יצדיק החלשת ההנחיות או אובדן הקשר.

## 6. Follow-up — בדיוק לפי המנגנון הנוכחי

- Follow-up הוא אופציונלי ואינו שלב שהמשתמש צריך להגדיר.
- לכל היותר Follow-up אחד בכל הראיון, כחלק מהניסיון הראשון עצמו.
- רק לאחר השלמת השאלה הראשית וקבלת המוכנות הנדרשת בשרת.
- נדרשות לפחות 600 שניות שנותרו לפי שעון השרת: 10:00 מאפשר, 9:59 אינו מאפשר.
- משתמשים רק בנוסח המדויק שהשרת אישר, עם הגרסה שנשמרה. המודל אינו ממציא שאלה חלופית.
- ניתוק וחיבור מחדש משחזרים את אותו Follow-up ואינם יוצרים נוסף.
- לאחר השלמתו מסיימים. אם אינו מתאים או אין מספיק זמן, מסיימים ללא Follow-up.

הדגל `INTERVIEW_FOLLOW_UP_ENABLED` נשאר פעיל בהגדרות ההשקה. קוד הליבה והבדיקות של מנגנון זה נשמרים.

## 7. ראיון אורח אחד — הגדרה מדויקת

זהות אורח נוצרת לאחר פעולת התחלה יזומה. לא יוצרים משתמשי אורח בכל צפייה בדף. הגישה לראיון נשענת על זהות מאומתת מאחורי הקלעים, בלי לבקש מהמשתמש פרטי הרשמה.

| אירוע                          | מה קורה לניסיון הראשון         | חוויית המשתמש                   |
| ------------------------------ | ------------------------------ | ------------------------------- |
| סירוב מיקרופון / טווח ללא מלאי | לא נצרך                        | מתקנים ומנסים שוב               |
| יצירת ראיון לפני חיבור קולי    | משוריין בלבד                   | מוצג מצב מתחבר                  |
| כשל ספק לפני הפעלת קול         | השריון משתחרר באופן בטוח       | ניסיון חוזר ללא הרשמה           |
| הפעלת קול מוצלחת ראשונה        | הניסיון נצרך ונקשר לאותו ראיון | מתחילים את הראיון המלא          |
| לחיצה כפולה / שתי לשוניות      | לכל היותר שריון אחד והפעלה אחת | חוזרים לאותו ראיון              |
| רענון / ניתוק זמני             | לא נוצר ניסיון חדש             | ממשיכים לפי מנגנון החיבור הקיים |
| סיום                           | נשאר נצרך                      | סיכום והצעת הרשמה               |
| נטישה אחרי תחילת קול           | נשאר נצרך                      | סיכום חלקי והצעת הרשמה          |
| מחיקת ראיון                    | אינה מחזירה ניסיון             | אין אפשרות לעקוף כך את המכסה    |
| הרשמה                          | הראיון והניצול נשמרים          | אפשר להמשיך כמשתמש רשום         |

שריון, הפעלה וצריכה נעשים בעסקה אטומית עם הגנות כפילות בבסיס הנתונים. אין להסתמך על `localStorage`, כפתור מושבת או מזהה ראיון שנשלח מהדפדפן כדי לאכוף ניסיון יחיד. כל מסלולי יצירת הראיון, כולל פונקציות SQL ישנות, כפופים לאותו כלל.

ניתוק אינו לבדו נטישה יזומה. משתמשים במנגנון החיבור והרשאת הקול הקיים ומגדירים בביצוע את המעבר הסופי בעת פקיעתו. כל עוד הראיון בר־המשך חוזרים אליו; לאחר מצב סופי מציגים הזמנה להרשמה. סגירת חלון אינה מאפשרת להציג מודאל לאחר הסגירה, ולכן ההזמנה מוצגת בביקור הבא אם הזהות עדיין זמינה.

תקלה טכנית לאחר תחילת הראיון קודם כול מנסה לשחזר את אותו ראיון. אין איפוס אוטומטי בלתי מוגבל של המכסה; שחזור חריג של הזכאות ייעשה רק בפעולת שרת מבוקרת ומתועדת.

ללא הרשמה אי אפשר להבטיח זיהוי של אדם יחיד בין מכשירים או לאחר מחיקת עוגיות. ההשקה תאכוף ניסיון אחד לזהות האורח ותוסיף מגבלות קצב ועלות כדי לצמצם ניצול לרעה. אין להבטיח מניעה מוחלטת של ניסיונות נוספים בדפדפנים אחרים.

## 8. סיום, נטישה והרשמה

בסיום תקין מוצג הסיכום ללא חובה להירשם כדי לראות את תוצאת הראיון הראשון. כפתור מרכזי: **שמירת הראיון ויצירת חשבון**. אפשרות משנית: **אולי אחר כך**. ניסיון להתחיל ראיון שני מחזיר להצעת הרשמה או התחברות.

בנטישה מוצגים סטטוס **הראיון לא הושלם**, מה שנשמר בפועל והצעת ההרשמה. לא מייצרים ציון סופי, כישלון או עדות כיסוי מלאכותיים. אין לדרוש שאלון רפלקציה כתנאי להצעת השמירה.

ההרשמה מבקשת את המינימום הדרוש לכניסה עתידית. שם תצוגה ופרופיל מפורט אינם תנאי לשמירת הראיון. מסלול אימייל מאומת חייב לעבוד בהשקה; ספקי Google/GitHub מוצגים רק לאחר שהוגדרו ונבדקו.

הארכיטקטורה המועדפת היא Supabase Anonymous Sign-In ולאחריו קישור אמצעי התחברות לאותה זהות. כך היסטוריית הראיון נשארת אצל אותו בעלים. יש לזהות אורח במפורש דרך `is_anonymous`, לא לפי עצם קיומו של מזהה משתמש. [התנהגות זהויות אורח ב־Supabase](https://supabase.com/docs/guides/auth/auth-anonymous).

בקישור אימייל יש להשלים אימות לפני קביעת סיסמה לפי זרימת הספק. בקישור OAuth משתמשים בקישור זהות מתוך סשן האורח. התחברות לחשבון שכבר קיים מחייבת מסלול נפרד: הוכחת שליטה בזהות האורח ובחשבון היעד, קישור שרת חד־פעמי ופג־תוקף ומיזוג אטומי של הראיון וכל הראיות. אין להעביר נתונים לפי אימייל או UUID שנשלחו בלבד. [Identity Linking](https://supabase.com/docs/guides/auth/auth-identity-linking).

במיזוג לחשבון קיים נשמרים שני הצדדים, נמנעת ספירה כפולה ונבנים מחדש רק הסיכומים המושפעים. קוד והרשאות מעבר לא נחשפים בכתובות או בלוגים. כשל באמצע משאיר אפשרות להמשיך את השמירה בלי לאבד את הראיון.

לאחר הרשמה חוזרים לסיכום או למסך הראיון. מציעים קישור קטן **רוצה גם הערכת יכולות?**, עם אפשרות לדלג. אין הפניה כפויה לאבחון או ל־Onboarding, גם בכניסות הבאות וגם בחזרה מאימות אימייל/OAuth.

מוצע לשמור נתוני אורח שלא שויכו לחשבון למשך 7 ימים מסיום או נטישה, בכפוף למימוש מחיקה מתוזמנת. זו מדיניות חדשה לביצוע. יש להציג את משך השמירה בפועל ואת התלות באותו דפדפן; אין להציג מחיקה אוטומטית לפני שחובר מנגנון הניקוי. רישום הזכאות המינימלי נשמר בנפרד כדי שמחיקת תוכן לא תאפס את הניסיון.

## 9. מסכים וניווט

| מסך                      | תוכן עיקרי                                              |
| ------------------------ | ------------------------------------------------------- |
| בית `/`                  | הגדרות קצרות והתחלה; קישור התחברות קטן                  |
| התחלה `/interviews`      | אותה זרימת התחלה, נגישה גם לאורח, בלי אבחון             |
| ראיון `/interviews/[id]` | סביבת הראיון הקיימת, קול, שאלה, עורך, זמן, חיבור ויציאה |
| סיכום / Review           | משוב וראיות לבעלים בלבד, עם הצעת הרשמה לאורח            |
| הרשמה / התחברות          | שמירת הראיון והחזרה אליו                                |
| משתמש רשום               | התחלת ראיון, היסטוריית ראיונות והגדרות                  |

מסלולי לימוד ותרגול קיימים אינם חלק מהניווט הראשי של ההשקה. לא מוחקים היסטוריה קיימת. אבחון זמין למשתמש רשום שבחר בו. משתמש רשום עם תרגול פעיל ישן לא נשלח אליו אוטומטית במקום ראיון: מוצגת אפשרות מפורשת לסגור את התרגול לפני התחלה, תוך שמירת העבודה ובהתאם למגבלת פעילות מקבילה הקיימת.

במובייל ההגדרות והכפתור נגישים ללא עומס; סביבת הקוד עוברת לפריסה אנכית. מצבי טעינה, שגיאת מיקרופון ושחזור קול יהיו ברורים בטקסט. אין תפריטי נושא או פרטי אלגוריתם בחוויית המשתמש.

## 10. FE, BE, Database ו־Endpoints

החלטת הפריסה: אפליקציית Next.js הקיימת על Vercel, עם Supabase מנוהל ל־PostgreSQL ול־Auth. ה־FE וה־BE נמצאים באותו פרויקט ובאותו דומיין; אין צורך בשלב זה בשרת API נפרד או ב־`api.` נפרד. הקול ממשיך במסלול הספק הקיים עם הרשאות קצרות־חיים שמונפקות בשרת.

| שכבה  | מה נשאר                                | מה צריך להוסיף או להתאים                                             |
| ----- | -------------------------------------- | -------------------------------------------------------------------- |
| FE    | עורך וראיון קיים                       | בית פשוט, טופס קצר, מצבי אורח והזמנת הרשמה                           |
| BE    | Server Actions ונתיבי realtime         | הבחנת אורח/רשום, התחלה ללא אבחון, מכסה, קישור חשבון ואכיפת Coverage  |
| DB    | היסטוריה, אירועי קול, קוד, הערכות, RLS | זכאות ניסיון, שריון אטומי, קישור חד־פעמי, מדיניות שמירה והרשאות אורח |
| AI    | ספק, Brain, Follow-up ומעריך קיימים    | אימות הרשאות ומגבלות שימוש לאורח; אין החלפת מנוע                     |
| תפעול | בדיקת סביבה, CI, build ו־health        | בדיקות מסע אורח, תקציב שימוש, ניטור ואישור השקה                      |

שינויים בבסיס הנתונים נכנסים במיגרציות חדשות, עם תאימות למידע הקיים. מתכננים רשומת זכאות ייחודית לבעלים עם מצב, מזהה ראיון, מועד שריון/פקיעה וצריכה; שמות הטבלאות הסופיים ייקבעו במימוש. בעלות וכל הגבלות האורח נבדקות גם ב־RPC, לא רק במסכים.

אורח יוכל לקרוא ולעדכן רק את הראיון שלו דרך הממשקים המוגנים הקיימים, ולקרוא את הסיכום שלו לאחר סיום. אורח אינו מקבל גישה לשאר אזורי המשתמש הרשום. יש להקשיח את המדיניות הקיימת, כי זהויות אורח משתמשות גם הן בתפקיד `authenticated` של Supabase.

הנתיבים הקיימים והיכולות החדשות מפורטים ב[מדריך הפריסה](public-launch-runbook.md). לפעולות התחלה, שמירה, סיום וקישור אפשר להשתמש ב־Server Actions; לא צריך להמציא REST endpoints כפולים.

## 11. פערים שהתגלו בבדיקת הקוד

אלו ממצאי קריאה שיש לאמת ולסגור בביצוע:

- חובת חשבון/Onboarding/אבחון מופיעה ב־proxy, ב־layout, בדף ההתחלה, ב־Server Action וב־SQL. שינוי מסך בלבד לא יספיק.
- `getAuthenticatedUser` והפניות `/signup` אינם מבדילים כיום בין אורח לרשום; הפעלת Anonymous Auth בלבד תיצור הפניות שגויות.
- יצירת אורחים וקישור זהויות כבויים בתצורת Supabase המקומית הנוכחית.
- יש מסלולי SQL ישנים להתחלת ראיון. כולם חייבים לעבור דרך אכיפת הזכאות או לאבד הרשאות הפעלה ציבוריות.
- אין כיום מכסת ניסיון אורח ומגבלות קול ייעודיות לפי זהות/קצב/תקציב כולל. מגבלת AI Coach אינה מכסת ראיון קולי.
- יש לאמת שפעולת ניתוק ספק משתמשת במזהה חיבור שבבעלות המשתמש ונשמר בשרת, ובודקת את תוצאת ההרשאה; אין לסמוך על `providerCallId` מהלקוח.
- סיום שיחה טבעי סוגר את הקול, בעוד פעולת השלמה בממשק דורשת חיבור קולי. יש לבדוק ולתקן כך שמצב סיום מאושר בשרת יאפשר סיכום והרשמה אחרי סגירת הקול, ללא חיבור מחדש. זהו חשד מקריאת קוד, לא תקלה ששוחזרה בדפדפן בבדיקה זו.
- `/api/health` בודק זמינות DB ונושאים פעילים. הוא אינו מוכיח שקול עובד, שקיימת שאלה לכל טווח או שאפשר להתחיל כאורח.

## 13. קריטריוני קבלה

- [ ] משתמש ללא עוגיות פותח קישור ויכול להתחיל ראיון בלי חשבון, אבחון או פרופיל.
- [ ] ארבע הבחירות בלבד נדרשות; המראיין הנוח נבחר מראש ואפשר להחליף לקשוח.
- [ ] כל שילובי השפה, הקוד, הטווח והזמן נתמכים או מציגים שגיאת מלאי אמיתית לפני צריכת ניסיון.
- [ ] הבחירה תמיד Coverage, כולל אחרי כיסוי מלא; נושאים, רמות וציוני עבר אינם הופכים לבחירות נוספות.
- [ ] סירוב מיקרופון, כשל ספק לפני הפעלה ולחיצה כפולה אינם גוזלים או משכפלים ניסיון.
- [ ] משתמש אינו יכול לפתוח ראיון שני דרך לשונית נוספת, RPC ישן, מחיקת ראיון או בקשה שנערכה ידנית.
- [ ] רענון וחיבור מחדש שומרים על אותו ראיון, קוד, זמן, Brain ו־Follow-up.
- [ ] המראיין הנוח והקשוח שומרים על ההבדלים הנוכחיים באנגלית ובעברית.
- [ ] Follow-up נשאר אופציונלי, יחיד, מאושר בשרת, עם בדיקות גבול 600/599 שניות.
- [ ] סיום טבעי של המראיין מגיע לסיכום גם אחרי סגירת חיבור הקול.
- [ ] בסיום או נטישה מוצעת הרשמה; הסיכום הראשון נגיש בלי הרשמה, וראיון נוסף דורש חשבון.
- [ ] הרשמה ושיוך לחשבון קיים שומרים על כל הראיות, אינם כופלים כיסוי ומטפלים בכשל באמצע.
- [ ] אבחון אינו חוסם משתמש חדש או ותיק בשום שכבה, כולל חזרה מאימייל/OAuth.
- [ ] בדיקות RLS כוללות שלושה שחקנים נפרדים: מבקר ללא סשן, משתמש אורח אמיתי ומשתמש רשום; אורח נוסף אינו קורא את ראיון הראשון.
- [ ] הערכה חסרה או תקלה בספק מוצגות כהערכה זמנית; אין טענה שקוד הורץ אם לא הורץ.
- [ ] סודות אינם מופיעים בקוד לקוח, בתשובות API או בלוגים; ניסיונות קול מוגבלים ונמדדים בשרת.
- [ ] בדיקות יחידה רלוונטיות, integration, מסע דפדפן, lint, typecheck ו־production build עוברים על גרסת השחרור.
- [ ] מבוצע ראיון אמיתי מהדומיין הציבורי, גם בעברית וגם באנגלית, כולל סיום, הרשמה וחזרה להיסטוריה.

יעדי מדידה ראשוניים, שטרם נמדדו: רוב המשתמשים מגיעים ללחיצה על התחלה בתוך פחות מדקה; יעד p95 להפעלת קול הוא עד 10 שניות לאחר מתן הרשאת מיקרופון ברשת נתמכת. מודדים בנפרד כשלי הרשאה, שרת וספק; אין להציג יעדים אלו כהבטחת ביצועים שכבר הושגה.

## 14. מה נדרש מבעל המוצר לקראת העלייה לאוויר

שם הדומיין, גישה לפרויקט Vercel ולפרויקט Supabase ייעודי, מפתח ספק ה־AI דרך הגדרות הסודות, שירות אימייל להרשמה ותקציב שימוש להשקה. אין לשלוח סודות בתוך המסמך או לשמור אותם ב־Git.

אפשר להכין את החשבונות והדומיין במקביל למימוש. פתיחת הקישור לקהל הרחב עם הבטחת ראיון ראשון ללא הרשמה תיעשה אחרי השלמת מסע האורח ובדיקות הקבלה, לפי [רשימת ההשקה](public-launch-runbook.md).
